# 研报助手

自动生成《场外衍生品投资策略》一页通的桌面应用，供券商内部使用。

输入一句话需求，输出一份单页图文成品。全程使用真实数据，成文中每个数字均可回溯至来源。

> 一页通指单页图文密排的研究成品，非多页 Word 长报告。版式对标 0720 三份模板
> （券商板块 / AI 产业趋势 / 长鑫科技 IPO）。

---

## 生成流程

```
                          一句话需求
                               │
                               ▼
   ① 需求解析    识别事件、板块、代表标的；对需求中的市场判断做数据查证
                               │
                               ▼
   ② 摸底取数    按论点库全部判定所需字段取数，共 17 个字段
                               │
                               ▼
   ③ 触发判定    113 条论点逐条判定，得出本次被真实数据触发的论点
                               │
              ┌────────────────┴────────────────┐
              ▼                                 ▼
      数据触发的候选                     研报提炼的候选
      58 条判定，阈值机械判定            sources/ 内 PDF，
                                         逐字原文 + 表格原文，
                                         机械校验（仅 --pick）
              │                                 │
              └────────────────┬────────────────┘
                               ▼
   ④ 主轴选取    两类候选统一编号，选 2~3 条、尽量跨类别
                 默认自动选取；--pick 时由分析师勾选
                               │
                               ▼
   ⑤ 论述生成    只使用已取到的真实数据；数据与论点矛盾时须指出该逻辑不成立
                               │
                               ▼
   ⑥ 数字溯源    成文中每个数字逐个回指真值，对不上标记为可疑
                               │
                               ▼
   ⑦ 排版渲染    图表生成 + 一页通 HTML
                               │
                               ▼
                     一页通成品 + 缺口清单
```

**关键在于第 ③ ④ 步**：报告论证什么由本次的真实数据决定，而非由固定模板决定。
更换标的或时点，成立的论点组合随之改变，报告视角亦随之改变。

两条候选通道的可证伪性来源不同：数据触发靠阈值机械判定，可自动选用；
研报提炼靠分析师点开原文核对，因此**只在 `--pick` 模式下出现，不能自动选取**。

## 运行方式

### 主路径：给定一句话需求

```bash
python main.py -b "昨晚SK海力士发了业绩，芯片板块最近明显回调，有无相关板块建议？"
```

系统解析出主题、事件、涉及板块与代表标的，并对需求中的市场判断（如"最近明显回调"）
以真实数据查证，返回支持或不支持的结论。

### 辅路径：扫描市场推荐选题

```bash
python main.py
```

先输出候选主题清单，再按序号生成，支持多选：

```bash
python main.py 1 4
```

成品输出至 `output/`。每份一页通同时并排产出一份 `*_缺口清单.md`，
记录哪些字段未取到及其原因、需求中提到但数据源不提供的外部事实、撰写环节漏写的逻辑、
校验器标出的可疑数字，以及本次引用的研报出处。该文件仅供内部使用，不随一页通对外发出。

### 人工选取论证角度：`--pick`

```bash
python main.py -b "券商板块最近怎么样，有没有配置价值？" --pick
```

默认由系统从触发结果中自动选取 2~3 条。加 `--pick` 后，系统先完成摸底取数与触发判定，
将本次被真实数据触发的论点按类别分组输出（含方向与实测依据），由分析师输入序号勾选，
系统仅负责将选中的论点组织成文。

```
── 数据触发（行情数据阈值判定）──────────────
【盈利/基本面类】
   1. E1   盈利改善　[看涨]
      依据：归母净利同比 +16.67%
【资金/筹码类】
   4. F1b  资金逆势流出　[看跌]
      依据：区间+1.47%、资金-99.20亿

── 研报提炼（需核对原文后再选）────────────────
【供需/产业格局类】
  33. 英伟达与海力士签署合计约 USD 500bn 多边协议，被市场认为循环融资　[看跌]
      华泰证券《SK海力士：短期情绪错杀 长期版图重塑》2026-08-02 p1 · 4天前
      原文：近期英伟达与海力士及 SK 集团分别签署合计约 USD 500bn 的多边协议…
...
请勾选作正文主轴的序号（空格分隔，建议 2~3 条）
  > 1 4 33
```

两类候选统一编号、混合选取。直接回车则交回系统自动选取。

若选中的论点方向相反，正文如实呈现分歧；若方向全部一致，系统提示"报告不会呈现分歧"。
卖方研报系统性偏多头，而本产品的主要风险是看漏下行风险，故将方向集中度显式提示，
但不作阻拦。

> 研报观点仅在 `--pick` 模式下出现。其可信度来源是分析师核对原文，而非阈值判定，因此不能自动选取。不加 `--pick` 时系统只使用 58 条数据触发的论点。

## 研报文档通道

论点库中渗透率、国产化率、海外龙头业绩这类数据，行情接口结构性地不提供，只能取自研报。将当次需要的研报 PDF 放入 `sources/`，系统从中提炼观点候选：

```bash
python -m core.docs
```

```
● [供需/产业格局类] 2026年资本支出将超过40万亿韩元，加速扩产　（看涨）
    华创证券《SK海力士…FY2026Q2业绩点评》2026-08-02 p3 · 4天前
    原文：由于生产计划加快和投资规模扩大，预计 2026 年的资本支出将超过 40 万亿韩元。
```

每条候选均附逐字原文、页码、出处与时效，可据此核对至研报原句。

**模型只做抽取，不做生成。** 观点必须是研报中明确表达的，且观点中的每个数字都要能在
所附原文中找到。校验按数值比对，机械执行，不依赖模型自觉；改写、杜撰、数值漂移均被拦下。

数字取自表格时，模型须另行逐字引出所读的表头行与数据行（`表格原文`）。该段同样逐字回查
文档，改写即整条作废——由此"数字 → 所引表格行 → 文档"的链条保持完整，而不是放宽成
"数字在文档某处出现即可"。

> **`sources/` 是工作台，不是资料库。** 研报时效性短，季度业绩点评过一个季度即基本失效。
> 建议每次生成前放入当次所需的研报，生成后清空。超过 90 天的会被标注内容可能失效。
> 引用的出处会固化进成品，原 PDF 删除不影响报告的可追溯性。
>
> `references/` 存放的是对标用的成品模板（0720 三份一页通），不参与生成。

## 成品结构

```
核心结论（三重逻辑一句话 + 推荐方向）        ← 印在最上，最后生成
  ├─ 策略逻辑一   大数字卡 + 图 + 一句加粗结论
  ├─ 策略逻辑二   同上
  ├─ 策略逻辑三   同上
  ├─ 挂钩标的与推荐结构                      ← 接 OptionHelper
  └─ 数据来源 + 风险提示
```

核心结论印在最上但最后生成：先完成各条逻辑的论证，再回头浓缩。

## 论点库

`THESIS_LIBRARY.md` 是一份人工维护的 Markdown 表格，**113 条论点、9 大类**。
每条论点定义一种可复用的论证方式：

| 列 | 作用 | 例（V1 估值历史低分位）|
|---|---|---|
| 触发条件 | 何种情况下该条成立 | PE/PB 分位 < 30% |
| 所需数据 | 判定所依赖的数据 | PB/PE 及历史分位 |
| 市场状态特征 | 该条成立意味着什么 | 方向=看涨；价格位置=低位；确定性=高 |

九大类：估值、盈利/基本面、供需/产业格局、资金/筹码、情绪/交易、事件/催化、
宏观/流动性、扩散/映射、轮动/相对强弱。

> 情绪/交易类与衍生品关联最紧：波动率既是期权定价的核心输入，
> 也是"高波动对应高票息"一类论证的直接依据。

**多空对称**：每条方向性论点都有对称面，阈值亦对称（低分位 <30% ↔ 高分位 >70%）。
看跌论点的用途不是劝退客户，而是：①导向看跌方向的结构；②约束结构参数
（估值处高位则敲入线宜更低）；③支撑合规风险提示。

**扩充论点只需修改该 Markdown，不改代码**，但只有注册了判定函数的论点才会被触发。
当前已接判定 58 条——这是观点多样性的实际上限。

## 数据可信性保障

市场分析的本质是"真实数字 + 对数字的解读"。数字不可信则整份报告不可信。
全流程据此划分职责：

| 环节 | 职责 | 限制 |
|---|---|---|
| 规划 | 选取论证角度 | 不接触任何数字 |
| 取数 | 查取真实数据，并预先格式化为最终可读形式 | — |
| 撰写 | 只使用已取到的真实数据 | 不做任何换算，照抄格式化值 |
| 校验 | 逐个数字回指来源 | — |

**① 缺数据则留白，不填充。**
数据只有两种状态：真实取到的，或明确标注"数据待补"。未配置密钥时直接报错，
不以假数据替代。

**② 数值前置格式化。**
曾出现将 41.50 亿写成 414.98 亿（元至亿换算错位）。根因是让模型执行了换算。
现于取数环节即格式化为 `41.50亿元` / `1.46倍` / `2.48%`，撰写环节只照抄。
资金流向另将"净流入 / 净流出"写入文字——方向写反在投研中是致命错误。

**③ 证伪义务。**
论点是待检验的假设，不是既定结论。若真实数据与论点相悖——论点称"估值处历史低分位"而实测 PB 22.56 倍，或称"分红改善"而现金分红为 0——必须如实指出该逻辑不成立，
不得圆场。

> 该防线针对的是比"数字错"更隐蔽的一类错误：**数字全对，论断却是假的**。
> 曾有一份成品 8 个数字全部溯源通过，正文却写着"估值处于历史低分位"。

**④ 逐个数字溯源。**
成文中每个带单位的数字都要能回指到一个真实取到的值，对不上则标记为可疑待复核。校验同时识别方向词——"下跌 5.81%"对应真值 −5.81% 判为通过，"上涨 5.81%"则判为方向相反。

## 数据来源与口径

主数据源为 **iFinD（同花顺）**，akshare 作免费补充。字段分三类：

- **直接取**：PB、ROE、净利同比、股息率、资金流等
- **需加工**：历史分位、年化波动率、板块聚合、解禁压力、盈利多期趋势等
- **只能人工补**：海外公司业绩、渗透率、产业测算等研报口径数据

**板块口径采用整体法。** `板块PB = Σ市值 / Σ净资产`，而非各成分股 PB 的算术平均，
也非市值加权平均。早期用单只代表股代表整个板块出过问题：以刚上市的新股代表板块，
分红为 0、估值失真，直接导致论断错误。现取板块前 N 大成熟成分股（剔次新）聚合。

**同业对比自动推断，不依赖人工维护清单。** 按 iFinD 行业层级查找兄弟板块
（"电子-半导体-集成电路制造"对应同层的封测 / 设计 / 设备 / 材料），同层样本过少则自动升一级。
跨大类比较 PE 无意义——半导体 126 倍与证券 13.9 倍之间推不出"证券便宜"。

**静态数据缓存复用。** 行业分类、指数成分、历史序列这类当日不变的数据取一次存本地，
将调用配额留给真正时变的数据。

## 人工介入节点

系统不是全自动黑箱，有四个人工节点：

1. **选题确认**——辅路径下候选主题由人工勾选，不自动生成
2. **论点勾选**（`--pick`，可选）——选取哪几条论点组成正文主轴由分析师决定，
   系统只负责将选中的组织成文。不加则由系统按"尽量跨类别"自动选取
3. **缺口清单**——每份成品并排产出 `*_缺口清单.md`：缺什么字段、为什么缺、
   需求中哪些外部事实数据源不提供。**模型不得编造外部事实**。
   目前只能查看不能回填，回填仍需重跑
4. **成品复核**——校验器标出的可疑数字需人工确认

## 当前能力边界

**已实现**

- 一句话需求 → 一页通 HTML，全程真实数据、数字可溯源、论断可证伪
- 板块机会型端到端跑通，并以真实数据反复验证（含数据与论点矛盾时的表现）
- 113 条论点中 58 条已接判定，可被真实数据触发
- 研报文档通道：PDF → 观点候选，逐字原文 + 机械校验
- 人工勾选正文主轴论点（`--pick`）

**未实现**

- 人工补充面板（缺口目前只能查看、不能填写）
- PDF / Word 导出（现仅 HTML）
- 推荐结构与期权定价（接 OptionHelper，对方尚未完成）
- 图形界面与 exe 打包

**已知短板**

- 判定覆盖不均：资金/筹码 17 条已接 13 条、盈利/基本面 15 条已接 11 条，
  而供需产业格局（17 条）与扩散映射（9 条）判定为 0，这两类暂不参与自动触发。
  它们恰是产业逻辑最集中的部分，是报告视角仍显单薄的根因。目前经研报文档通道部分补足。
- 宏观类论点是市场级的，换标的判定不变。已评估过默认排除方案，最终未做——
  由分析师用 `--pick` 自行判断，系统不预先替人排除判断空间。
- 产业趋势型报告所需的产业口径数据（渗透率、中外产能对比、前瞻 PE）几乎全靠人工补充，
  自动化程度显著低于板块机会型。
- 触发阈值多为实测拍定的经验值，仍需按实际研报口径校准。
- 研报表格数列的自动抽取尚不稳定，图表主要仍来自行情数据。

## 项目结构

```
main.py                 端到端入口
THESIS_LIBRARY.md       论点库（113 条，改论点只改这里）
edb_check.py            宏观指标自查工具

sources/                当次要用的研报 PDF（工作台，用完清空）
references/             对标用的成品模板（0720 三份一页通），不参与生成
output/                 生成的一页通成品

core/
  ── 选题 ──────────────────────────────
  brief.py              需求解析（含市场判断查证、标的代码校验）
  topics.py             扫描市场推荐候选选题
  signals.py            市场信号采集 + 板块快照（iFinD 优先，akshare 兜底）
  genres.py             报告体裁（类型枚举 + 行文口吻参考）

  ── 数据 ──────────────────────────────
  provider.py           数据源抽象（iFinD / akshare）
  ifind_indicators.py   业务字段 → iFinD 指标代码映射
  schema.py             数据字段目录（含义 / 单位 / 取数方式）
  fetcher.py            取数层：多路分派 + 数值前置格式化
  universe.py           板块成分股（剔次新股）+ 板块名解析
  aggregate.py          板块整体法聚合（含杜邦净利率 / ROE、FY1 预测 PE）
  peers.py              同业对比（行业层级动态推断）
  history.py            历史序列与分位（估值 / 波动率 / 换手 / 成交额）
  fundamentals.py       盈利多期趋势 + 毛利率、机构持股历史分位
  flows.py              ETF 份额 / 两融余额 / 业绩预告
  unlock.py             限售解禁压力
  macro.py              宏观指标（EDB 只按 ID 取，每次核对指标名）
  docs.py               研报抽取（sources/ 的 PDF → 观点候选）
  rotation.py           轮动与相对强弱
  instruments.py        挂钩标的候选池（指数 / ETF，代码经实测校验）
  selection.py          标的择优（多维比较）

  ── 生成 ──────────────────────────────
  thesis.py             论点库解析 + 触发引擎（含人工勾选清单渲染）
  planner.py            论点规划（不接触数字；支持人工勾选模式）
  pipeline.py           编排：取数 → 触发 →（可选勾选）→ 规划 → 回填
  writer.py             论述生成（证伪义务）
  validator.py          数字逐个溯源
  config.py             密钥加载与网络配置

render/                 图表（数字卡 / 表 / 柱 / 折线 / 双轴柱线）、一页通排版、缺口清单
llm/                    DeepSeek 封装
```

## 配置

密钥存于 `config.local.json`（不进版本库），或通过环境变量提供。

```json
{
  "deepseek_key": "...",
  "ifind_account": "...",
  "ifind_password": "..."
}
```

LLM 使用 DeepSeek，默认模型 `deepseek-v4-pro`，可用 `DEEPSEEK_MODEL` 环境变量覆盖。

密钥不打包进 exe——可被反编译提取。分发时各人填写自己的密钥；
若需大范围推广，走公司内网后端代理，统一充值、限流与审计。
